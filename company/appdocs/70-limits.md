# 자원 한도와 강제 중지
> 메모리, CPU, 데이터, 프로세스, 임시 공간의 상한과 플랫폼이 앱을 멈추는 조건.
keywords: 메모리, memory, RAM, OOM, CPU, 한도, limit, 제한, 상향, 느림, 느려, 종료, 중지, 강제, killed, 프로세스, 스레드, 임시, tmp, 용량, 성능, 워치독

## 기본 한도
| 항목 | 기본값 | 넘으면 |
|---|---|---|
| 메모리 | 192 MB (앱별 조정) | 한도의 1.5배가 15초(5초 샘플 3회) 이상 지속되면 중지. 커널 한도(rlimit/cgroup)가 있으면 그 전에 `MemoryError` |
| CPU | 1코어의 100% | 1분(12회 샘플) 연속 초과하면 중지 |
| 데이터 | 128 MB | 80%에 경고, 100%에 중지 |
| 프로세스/스레드 | 64 | 새 프로세스·스레드 생성 실패 (`BlockingIOError`, `RuntimeError: can't start new thread`) |
| 열린 파일 | 4096 | `OSError: Too many open files` |
| 임시 공간 `TMPDIR` | 64 MB | 쓰기 실패 (`No space left on device`) |

- 서버 전체의 메모리가 부족해지면 플랫폼이 가장 무거운 앱부터 정상 종료(SIGTERM)시킨다.
- 강제 중지된 이유는 앱 페이지(`/_app`)와 관리 화면에 표시된다 ("메모리 한도 초과", "CPU 한도 초과", "데이터 한도" 등). 앱 페이지에서 다시 시작할 수 있지만 원인을 고치지 않으면 반복된다.

## 한도 안에서 동작하게 만들기
- 큰 파일이나 테이블 전체를 한 번에 메모리에 올리지 않는다. `pandas.read_csv(chunksize=…)`, SQL에서 `LIMIT`/`OFFSET` 또는 커서로 나눠 처리한다.
- 요청마다 무거운 계산을 반복하지 않고 결과를 테이블이나 `platform.state`에 캐시한다.
- 무한 루프, 요청 안의 `time.sleep`, 큰 재귀는 CPU 한도와 헬스 체크 실패로 이어진다. 백그라운드 작업은 `BackgroundTasks`로 짧게 유지한다.
- 파일과 DB 연결은 `with` 문으로 닫는다.
- 한도 상향은 배포 요청 폼의 "메모리"·"데이터 저장 공간" 항목으로 요청한다. 요청 페이지에 서버가 감당할 수 있는지가 함께 표시되고, 관리자가 판단한다.
